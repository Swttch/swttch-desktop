# Swttch Desktop MVP PRD

> 작성일: 2026-10-08 (한국 시간)
> 상태: 검토용 초안. 확정 범위와 제안을 구분한다. 구현·사용자 검수 전.
> 결정 근거: [MVP 기획과 인계](mvp-planning.md)
> 구현 설계: [MVP 기술스펙](mvp-technical-spec.md)

## 목표와 완료 조건

사용자가 설치한 **Swttch**에서 앱 계정으로 로그인하고, 로컬 프로젝트를 선택한 뒤 기존 채팅 웹앱으로 에이전트와 한 턴을 완료한다.
MVP의 작업 영역은 패널 하나와 탭 하나다. 탭은 채팅 웹앱을 담으며, 채팅 세션과 동일한 개념이 아니다.

앱 실행이나 백엔드 연결만으로 MVP 완료를 선언하지 않는다. 실제 CLI 응답, 필요한 권한 상호작용, 응답 완료까지 확인한다.

## 확정 범위

- Electron과 localhost 브라우저에서 동일한 프론트 및 공통 기능을 실제로 사용한다. [핵심 원칙](core-principles.md), 2026-10-08 사용자 확정.

- Electron 설치형 앱, 기존 Node.js 백엔드 및 채팅 웹앱 재사용.
- 필수 앱 로그인, 로컬 프로젝트 선택, 기존 채팅 기능으로 한 턴 완주.
- 앱 로그인은 Google·GitHub·이메일을 모두 지원한다 (2026-10-08 사용자 확정).
- 기존 플러그인 사용자는 기존 Swttch 계정을 재사용할 수 있어야 한다 (같은 날 사용자 확정). 기존 계정의 식별 및 연동 경로는 기술 확인이 필요하다.
- 앱 홈 `~/.swttch`, 로컬 SQLite, 중앙 API와 PostgreSQL.
- 중앙 API의 초기 역할은 계정과 라이선스 관리.
- 대상 OS는 macOS·Windows·Linux. 설치 프로그램·npm·Homebrew Cask 설치 경로 제공.

여러 패널·탭, 분할, 터미널 탭, 프로젝트·세션 중앙 동기화는 후속 범위다.
가격·기능 제한·무료 체험·기기 수 제한은 정의하지 않는다.

## 첫 실행 흐름

아래 화면 순서와 실패 처리는 제안이며, 인증 구현 방식과 함께 검토한다.

| 단계 | 사용자 행동과 결과 | 실패 시 제안 |
|---|---|---|
| 앱 실행 | 창이 열리고 준비 상태를 보여준다 | 실행 실패 원인과 재시도 제공 |
| 앱 로그인 | 앱 계정 인증을 완료한다 | 취소·실패는 로그인 화면에 남고 재시도 가능 |
| 프로젝트 선택 | 네이티브 폴더 선택으로 작업 폴더를 지정한다 | 취소는 선택 전 상태 유지, 접근 불가는 다시 선택 가능 |
| 채팅 준비 | 로컬 백엔드에 연결하고 CLI 설치·인증 상태를 확인한다 | 설치 또는 CLI 인증이 필요하면 해당 준비 경로 안내 |
| 첫 메시지 | 사용자가 입력한 메시지를 지정 폴더의 CLI에 전달한다 | 전송 실패 표시, 성공으로 처리하지 않음 |
| 응답 | 기존 스트리밍·권한 UI를 사용하고 완료 상태에 도달한다 | 권한 거부·실행 오류를 기존 채팅 UI로 표시 |

앱 로그인과 Agent CLI 로그인은 각각 충족해야 한다. 둘 중 하나로 다른 하나를 대신하지 않는다.
CLI 자동 설치 여부와 지원할 Agent 종류는 추가 결정이 필요하다. 최초 검증은 기존 Claude Code 경로를 사용하는 안을 제안한다.

## 수용 기준

| ID | 확인할 결과 | 상태 |
|---|---|---|
| AC-01 | 앱 표시 이름이 Swttch이며 패널 하나·탭 하나에 기존 채팅 웹앱이 표시된다 | 확정 범위 |
| AC-02 | 앱 로그인 없이 새 에이전트 작업을 시작할 수 없다 | 확정 범위 |
| AC-03 | 선택한 로컬 폴더가 실제 CLI 작업 디렉토리와 일치한다 | MVP 흐름 |
| AC-04 | CLI 미설치·미인증 상태를 준비 완료와 구분하고 사용자가 해결할 경로를 제공한다 | 제안 |
| AC-05 | 실제 메시지 전송 후 스트리밍 응답과 완료 상태를 관찰한다 | MVP 흐름 |
| AC-06 | 권한 요청을 승인·거부할 수 있고, 중단과 오류를 성공으로 표시하지 않는다 | 기존 기능 재사용 |
| AC-07 | 앱 로그인 실패·취소, 폴더 선택 취소, 백엔드 준비 실패에서 다시 시도할 수 있다 | 제안 |
| AC-08 | 로그인 유지·로그아웃·앱 재실행 결과가 확정된 인증 및 종료 정책과 일치한다 | 정책 결정 대기 |
| AC-09 | 백엔드 장애 후 화면 상태와 재연결 결과가 확정된 복구 정책과 일치한다 | 정책 결정 대기 |
| AC-10 | macOS·Windows·Linux의 설치 산출물에서 실행과 한 턴 완주를 확인한다 | 확정 범위 |
| AC-11 | npm 설치 경로와 macOS Homebrew Cask 설치 경로에서 앱 실행을 확인한다 | 확정 범위 |
| AC-12 | 기존 JetBrains 및 standalone의 실행·데이터 경로에 회귀가 없다 | 보존 원칙 |
| AC-13 | Google·GitHub·이메일 각각으로 앱 로그인할 수 있다 | 사용자 확정 |
| AC-14 | 기존 플러그인 사용자가 기존 Swttch 계정을 재사용하고, 기존 계정과 라이선스 관계가 보존된다 | 사용자 확정, 연동 계약 대기 |
| AC-15 | localhost 브라우저에서 동일 React + TypeScript 셸로 프로젝트 선택·탭·채팅 기능을 실제로 사용한다. Electron preload 없이도 공통 흐름을 완료한다 | 사용자 확정, 현재 미구현 |

실제 검증에는 화면 전환, 선택 폴더, 실행 환경, 응답 완료 결과를 남긴다. 한 OS에서의 결과를 다른 OS 검증으로 대체하지 않는다.

## 구현 전에 결정할 정책

| 항목 | 제안 또는 선택지 | 아직 결정하지 않은 것 |
|---|---|---|
| 계정 | Google·GitHub·이메일 지원 및 기존 Swttch 계정 재사용은 확정 | 인증 공급자, 이메일 인증 방식, 기존 계정 식별·연동, 중앙 API 계약 |
| 로그인 유지 | 재실행 시 유효한 앱 인증 복원 | 만료·갱신·로그아웃 중 실행 작업 처리 |
| 네트워크 장애 | 첫 로그인 실패는 재시도 제공 | 기존 로그인 사용자의 오프라인 작업 허용 여부 |
| 라이선스 | 계정과 권한 정보를 중앙 API에서 관리 | 발급·검증 방식, 정책 없음 상태의 동작 |
| 창 닫기·종료 | 창 닫기와 앱 종료를 구분하는 안 | OS별 동작, 실행 중 작업 확인 및 중단 정책 |
| 재실행 | 대화 복원, 에이전트 작업은 자동 재개하지 않는 안 | 사용자 승인 전 제안 |
| 백엔드 장애 | 재시작·같은 화면 재연결, 작업 자동 재개 없음 | 자동 복구 여부·재시도 한도·실패 화면 |
| 데이터 | 데스크탑 메타데이터는 SQLite, CLI 원본은 그대로 유지 | 플러그인 데이터 공유·이관·공존 정책 |

## 작업 순서

각 항목을 별도 검수 단위로 진행한다. 아래 체크는 구현·사용자 검수 후 갱신한다.

- [ ] 이 PRD의 첫 실행 흐름과 필요한 정책 확정.
- [ ] 기술스펙 확정: 계정 API, 런타임, 데이터, 종료·복구 경계.
- [ ] 독립 비공개 저장소 및 빌드 진입점 마련.
- [ ] Electron 단일 패널·탭에서 기존 채팅 앱 연결 검증.
- [ ] 공통 로컬 API와 호스트 어댑터로 Electron·localhost 브라우저 동등 실행 구현 및 Codex 브라우저 검증.
- [ ] 필수 앱 로그인 및 로컬 프로젝트 선택 연결.
- [ ] SQLite와 중앙 계정·라이선스 API 연결.
- [ ] 확정한 종료·복구·재실행 동작 검증.
- [ ] OS별 패키징 및 설치 경로 검증.

셸 연결만 검증한 단계는 MVP 전체 완료가 아니다. 로그인 우회를 제품 동작으로 채택하지 않는다.
