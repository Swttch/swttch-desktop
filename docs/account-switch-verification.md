# 계정 전환과 모든 계정 사용량 조회

> 2026-10-12. 구현·검증 완료 및 사용자 UI 검수 반영 기록입니다.

## 변경

- 실제 저장 계정 ID는 `acc-<UUID>`입니다. 데스크탑 API의 잘못된 `acc:` 검사로 전환이 차단되던 문제를 수정했습니다.
- 전환은 기존 CCG `SWITCH_ACCOUNT`를 사용합니다. 저장된 대상 인증이 만료됐으면 전환 전에 갱신하고, 전환 완료 후 활성 계정과 사용량을 다시 읽습니다.
- 비활성 계정은 자신의 저장 인증을 확장킷 SDK에 전달해 실제 사용량을 조회합니다. 이 조회는 현재 로그인 슬롯을 바꾸지 않습니다.
- 만료된 저장 OAuth 인증은 설치된 Claude Code에서 확인한 production refresh 계약으로 갱신합니다. 원본 account-store의 reader/writer를 재사용하고 갱신된 저장 snapshot만 기록합니다. 토큰은 Node 안에서만 처리합니다.
- 계정별 사용현황은 계정 전환 드롭다운에 통합했습니다. 목록 위에는 Claude 로고·이름과 작은 전체 새로고침 아이콘을 표시합니다. 각 계정은 같은 아바타·이름·이메일·현재 계정 체크와 배터리·세션 잔여 퍼센티지를 표시하며, 호버와 키보드 포커스 툴팁에서 초기화 시각을 확인할 수 있습니다. 사용량 상세의 중복 계정 목록은 제거하고 세션 (5시간)·주간 (7일) 상세와 기여도는 유지합니다.
- 개별 새로고침 버튼은 제거하고 작은 전체 새로고침 아이콘을 남겼습니다. 프론트 사용량 조회는 전체 계정 쿼리 하나로 통일해 1분마다 갱신합니다. 하단바·현재 계정 상세·계정 목록이 같은 결과를 사용합니다.
- 계정 드롭다운의 Claude 헤더는 구분선 없는 옅은 그룹 라벨입니다. 계정 선택·호버 영역은 배터리를 포함한 행 전체이며, 저장 메타데이터의 상대 시각은 표시하지 않습니다. 계정별 조회 오류와 마지막 성공 조회 시각은 배터리 왼쪽의 작은 경고 삼각형 툴팁으로 표시합니다. 이 표현 변경은 계정 드롭다운 내부에만 적용합니다.
- 활성 계정은 요약과 목록이 같은 SDK reader를 공유합니다. 원본 usage-cache의 계정별 snapshot·cooldown도 재사용해 다른 CCG 창과 요청 제한 상태를 공유합니다.
- 요청 제한·갱신 실패 시 해당 계정의 마지막 성공 값과 실패 안내·성공 조회 시각을 함께 표시합니다. 과거 값을 새 조회 성공으로 표시하지 않습니다.
- 전환 전 요청이 늦게 끝나도 새 계정 표시를 덮지 않도록 조회 세대와 프론트 변경 세대를 검사합니다. 활성 프로필이 목록 계정과 달라지면 행별 오류로 처리하며 다른 계정 값을 표시하지 않습니다.

## 실제 검증

1. 기존 Max에서 저장된 Pro 계정으로 UI에서 전환했습니다.
2. SDK 프로필·플랜이 Pro로 바뀌고, 같은 browser-demo 작업 디렉터리의 `claude auth status --json`에서도 `subscriptionType: pro`를 확인했습니다.
3. UI에서 새 세션을 만들고 실제 CLI 응답 `SWTTCH_ACCOUNT_SWITCH_OK`를 확인했습니다. 원본 JSONL에도 응답이 기록됐습니다. 세션 ID: `dd4bd0fa-29ab-4845-8085-db503e97ae33`.
4. Pro가 활성인 상태에서 비활성 Max의 실제 조회와 개별 새로고침을 확인했습니다. 조회 시각이 갱신되고 세션 4%·주간 2%가 표시됐으며, 활성 계정은 Pro로 유지됐습니다.
5. Pro 사용량도 새 응답 후 세션 2%로 갱신됐습니다. 전체 새로고침 요청에서 Max의 공급자 429가 발생해 계정별 실패 표시·마지막 성공 값·공유 cooldown을 보완했습니다. 공급자의 요청 제한 중에는 새 원격 조회가 성공했다고 간주하지 않습니다.
6. 검증 후 원래 Max 계정으로 복원했고 CLI 인증 상태에서도 `subscriptionType: max`를 확인했습니다.
7. 계정 행 통일 후 내장 브라우저에서 현재 계정 체크·동일 아바타·잔여 배터리 표시와 비활성 계정의 초기화 시각 호버 툴팁을 확인했습니다. 전체 새로고침 시 네트워크에는 `POST /desktop-api/account-usage-refreshes` 하나만 발생했고 별도 현재 계정 사용량 요청은 없었습니다.

빌드와 테스트 60개가 통과했습니다. 저장 인증 갱신·토큰 미노출·현재 슬롯 유지·원본 필드 보존·공유 reader·cooldown·과거 값 표시·전환/조회 겹침과 API 인증 보호를 검증합니다. Electron은 실행하지 않았습니다.

캡처는 로컬 `artifacts/account-switch/`에 보관합니다. 실제 계정·세션 정보가 포함되어 공개 문서에 이미지를 복사하지 않습니다.
