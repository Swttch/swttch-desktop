# 공통 하단바 첫 구현 기술 스펙

> 2026-10-12. [제품 구상](shared-shell-controls.md)의 첫 구현 범위입니다.

## 기능 대조와 이번 범위

| 기존 채팅 상단바 기능 | 현재 연결 방식 | 이번 처리 |
|-----------------------|----------------|-----------|
| 계정 사용량 | 채팅 페이지의 사용량 열기 이벤트 | 확장킷으로 기본 로컬 Claude 계정의 사용량을 공통 하단바에 제공 |
| 계정 전환 | 채팅 계정 선택 메뉴 | 기존 CCG의 계정 목록·전환을 하단 드롭다운에서 재사용. 계정 추가·관리는 기존 웹뷰 연결 |
| 예약 메시지 | 세션 Context의 패널 토글 | 유지. 세션별 조회·조작 계약 필요 |
| 백그라운드 작업 | Workflow Context의 패널 토글 | 유지. 공통 목록과 세션별 명령의 범위 결정 필요 |
| 터널 | 채팅의 터널 액션 | 유지. 대상·연결·소유권 확인 필요 |
| 설정 | 설정 페이지 또는 오버레이 열기 | 유지. 앱 설정과 채팅 설정 분류 필요 |
| 자산 | 기존 자산 모달 열기 | 유지. 공통 라이브러리 진입 계약 필요 |
| 새 탭 | 세션 Context의 호스트 요청 | 단일 작업 뷰의 기존 새 채팅 사용. 다중 탭은 23번 |
| 백엔드 연결·재시도 | 데스크탑 사이드바 하단 | 공통 하단바 오른쪽으로 이동 |

따라서 이번에는 채팅 상단바를 숨기지 않습니다. 남은 진입점을 공통 영역에 마련한 뒤 숨깁니다.

## 데이터와 API

- 데스크탑의 고정 의존성 `@swttch/extend-kit@0.7.3`, Node에서 `/battery` 동적 import. 프론트에서는 타입만 import합니다.
- SDK의 `getCredentials`, `isTokenExpired`, `getAccessToken`, `ClaudeCodeClient.oauth.getProfile/getUsage` 사용. 요청마다 최신 자격 증명을 읽으며 인증 갱신·계정 전환은 수행하지 않습니다.
- `GET /desktop-api/provider-usage`: 기본 로컬 계정의 profile·usage·오류·조회 시각. 인증된 로컬 앱 세션 필요.
- `POST /desktop-api/provider-usage-refreshes`: 수동 갱신. 기존 origin·세션·CSRF 검증 적용.
- 원본 profile·usage 키와 값을 보존합니다. 토큰·자격 증명·키체인 출력·외부 API 오류 원문은 응답과 로그에 넣지 않습니다.
- profile과 usage는 병렬 조회하며 부분 실패를 각각 표시합니다. 실패한 자료를 이전 계정의 값으로 대신하지 않습니다.
- 호스트 단위 60초 캐시·단일 진행 요청 병합. 수동 갱신은 최소 10초 간격, 429 응답의 Retry-After가 더 길면 해당 시간까지 대기합니다. 브라우저 Query도 60초마다 조회하며 비활성 창에서는 주기 갱신을 중지합니다.
- 인증 오류는 CLI 로그인 갱신 안내, API 키 인증은 구독 한도 조회 불가 안내, 나머지 오류는 네트워크·권한 확인 또는 재시도 안내를 표시합니다.
- DB에 계정·사용량·인증 정보는 저장하지 않습니다.

## 화면과 상태 경계

2026-10-12 하단 요약 개선: Claude 아이콘은 유지하고 이름 텍스트 대신 배터리 도형을 표시합니다. 비율은 `0% 5h · 2% wk` 형식입니다. 비율은 기존 사용률을 유지하고 배터리 채움은 플러그인과 같은 5h 잔여 한도입니다. 색상은 플러그인과 동일하게 잔여 50% 초과 초록(`#22c55e`), 20% 이상 노랑(`#eab308`), 20% 미만 빨강(`#ef4444`)이며 20% 미만에서는 reduced-motion을 존중하며 점멸합니다. 하단과 상세 패널의 새로고침은 사용자가 선택한 Heroicons `arrow-path`를 공유합니다. 실제 브라우저에서 아이콘·색상·표기와 상세 패널 새로고침 동작을 확인했습니다.

- 기존 토큰을 사용하는 전체 너비 2rem 하단바. 사이드바 표시 여부와 페이지에 관계없이 유지합니다.
- 왼쪽 Claude 버튼: 사용 기준 5시간·주간 비율. 클릭하면 로컬 계정·전체 사용 한도·초기화 시각·추가 사용 상태·수동 갱신을 표시합니다. 알려지지 않은 한도도 최종 소비자인 프론트에서 표시하며 기본 한도의 중복 표현만 제거합니다.
- 오른쪽 연결 버튼: 기존 workspace Query/SSE의 starting·ready/chat·error를 표시. 상세 패널의 재연결은 기존 backend-restarts API와 복구 정책을 사용합니다.
- 로딩·자료 없음·부분 실패·전체 실패·수동 갱신 중 상태를 구분합니다. 오류를 0%로 표시하지 않습니다.
- 패널은 위로 열리며 너비·최대 높이를 화면에 맞추고 스크롤을 제공합니다. 좁은 화면에서는 요약 비율을 접고 버튼은 유지합니다. Esc·바깥 클릭으로 닫고 Esc에서 호출 버튼으로 포커스를 복원합니다.
- 사용량·계정·CCG 연결 드롭다운은 모두 공통 `Dropdown.tsx`의 Tippy 클릭 팝오버를 사용합니다. 버튼과 팝오버만 내부로 판정하며, 하단바 빈 영역 클릭은 바깥 클릭으로 처리합니다. 하나를 열면 다른 것은 닫고, 상세 내부 클릭은 열린 상태를 유지합니다. 툴팁 표시가 드롭다운을 닫지 않도록 구분합니다.
- 하단바 왼쪽은 계정 아바타 → 짧고 옅은 세로 구분선 → Claude 아이콘·배터리·사용률 → 새로고침 순서입니다.
- 사용량은 호스트의 기본 Claude 로그인 기준입니다. 특정 채팅 탭이 다른 계정을 사용하면 일치하지 않을 수 있으며 UI에 이 범위를 명시합니다.
- 리소스·포트·원격 관리, 상단바 완전 숨기기, STT는 이번 범위에 포함하지 않습니다.

### 계정 드롭다운 연결과 플러그인 디테일 일치

- `GET /desktop-api/accounts`는 CCG `GET_ACCOUNTS` 원본 응답을 보존합니다. `PUT /desktop-api/active-account`는 기존 `SWITCH_ACCOUNT` 실행 후 활성 계정을 다시 조회합니다. 변경 요청은 세션·origin·CSRF 검증을 적용합니다.
- 계정 추가·관리는 기존 `/switch-account`, `/settings/account` 웹뷰를 인증된 iframe으로 엽니다. 인증·계정 저장·전환 비즈니스 로직을 셸에 복제하지 않습니다.
- 다른 웹뷰에서 계정을 바꿔도 `ACCOUNTS_CHANGED`를 받아 목록·SDK 사용량 캐시를 초기화합니다. 이전 계정의 진행 중인 조회가 뒤늦게 캐시를 채우지 않도록 무효화 세대를 검사합니다.
- 기존 플러그인 기준으로 ID별 아바타 팔레트·두 글자 이니셜, 행 아바타 크기·간격, 이름 강조, 이메일 보조색, 최근 사용 시각과 Heroicons 설정 아이콘을 맞춥니다. 현재 계정은 선택 불가하지만 투명도는 1로 유지합니다.
- 실제 브라우저에서 저장 계정 목록, 현재 계정 표시, 계정 추가·관리 화면과 좁은 화면 배치를 확인했습니다. 테스트 51개와 빌드가 통과했습니다. 실제 사용자 계정 전환은 수행하지 않았고 전환·인증 보호·캐시 무효화는 시험 계정으로 검증했습니다.

## 검증

- 실제 SDK의 HTTP 전송을 로컬 시험 API와 연결해 원본 필드 보존·토큰 미노출·병렬 요청 병합·캐시·429 대기·부분 실패를 검증합니다.
- 브라우저에서 실제 기본 계정의 프로필·사용량 조회, 새로고침, 연결 상세, Esc·바깥 클릭 및 좁은 화면 배치를 확인합니다.
- 백엔드 단절·재연결은 기존 복구 동작을 재사용합니다. 새 UI의 오류·재연결 경로는 격리된 시험 호스트로 검증하고 사용자의 실행 중인 CCG는 종료하지 않습니다.
