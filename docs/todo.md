## 실행·복구 검증

- [x] 01. Electron에서 프로젝트 선택·새 세션·기존 세션 진입·실제 CLI 응답의 전체 흐름을 검증.
  - 근거: 2026-10-11 실제 Electron UI에서 프로젝트 선택, 새 세션 응답 `SWTTCH_NATIVE_NEW_OK`·`SWTTCH_RESTORE_OK`, 기존 세션 응답 `SWTTCH_RESUME_OK`를 확인. CLI 원본 JSONL에도 응답 완료 기록 확인.
- [x] 02. 앱 시작 시 CCG 자동 실행, 정상 앱 종료 시 확인창과 앱 소유 백엔드 정리를 검증.
  - 근거: 기존 실제 Electron 소유권 검증에 더해, 이번 격리 CCG 런타임의 시작·종료와 열린 WebSocket을 포함한 호스트 정상 정리를 확인.
- [x] 03. 창 닫기·재실행에서 확인창과 마지막 프로젝트·세션 복원을 검증.
  - 근거: 창 닫기 확인창 취소 시 대화 유지, 종료 선택 시 호스트 정리, Cmd+Q 확인창, 다른 포트로 재실행 후 마지막 기존·새 세션 복원 확인. SQLite v10에 인증 정보 없이 프로젝트·세션 참조 저장.
- [x] 04. 사용자가 별도로 실행한 CCG 백엔드를 재사용하고 종료하지 않는지 검증.
  - 근거: Electron 실행·종료·호스트 복구 후에도 기존 CCG PID 13415와 19836 포트가 유지됨. 격리 검증 서버 19837만 종료.
- [x] 05. 백엔드 연결 단절·복구와 연속 세션 전환을 검증. 브라우저 자동화 없이 사용자가 조작할 때도 정상 동작해야 함.
  - 근거: 실제 UI의 새·기존 세션 전환 확인. 격리 CCG 종료 → 연결 종료 표시 → 재시도 → 연결 복구 → 같은 대화에서 `SWTTCH_RECOVERY_OK` 응답 완료. 제품에 자동화 코드를 주입하지 않고 일반 UI 조작 경로로 검증.
- [x] 06. 자동 재시작·작업 재개 여부와 실패 시 복구 정책을 정리하고 필요한 동작 구현.
  - 적용 정책: 연결은 자동 재시도, 살아 있는 서버는 유지, 종료된 CCG·로컬 호스트의 재실행은 사용자 선택, 중단된 작업과 메시지는 자동 재개·재전송하지 않음. 상세와 검증 범위는 [실행·복구](lifecycle-recovery.md) 참고.

  - CCG 백엔드·웹뷰, Electron·Node 런타임, SDK·라이브러리·네이티브 모듈 등 앱이 관리하는 전체 의존성의 버전과 배포 산출물을 관리. 각 의존성을 임의의 최신 버전으로 올리는 대신 앱 릴리스에서 정의하고 검증한 조합을 적용.
  - 사용자가 의존성을 개별 설치·업데이트할 필요 없이 앱 업데이트로 함께 반영되도록 구현. 업데이트 실패 시 버전 혼합을 방지하고 이전 정상 조합으로 복구하는 정책 및 실제 설치 산출물 검증을 포함.
  - 사용자가 독립 설치한 CCG·JetBrains 플러그인은 별도로 관리하며 덮어쓰지 않음. 독립 CCG 재사용 시 호환성을 확인하고 비호환이면 앱이 관리하는 런타임을 사용하는 정책을 정의.
