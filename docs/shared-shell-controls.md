# 데스크탑 공통 영역과 채팅 상단바 재배치 구상

> 작성: 2026-10-12. 제품 구상이며 구현 완료나 확정된 기술 스펙을 의미하지 않습니다.
> 연결된 할 일: 32번 확장킷 SDK 활용, 34번 공통 영역 재배치. 다중 탭·패널은 23~26번과 연결됩니다.

## 목적과 배경

JetBrains 플러그인에서는 개별 채팅 웹뷰의 상단바가 세션 탐색과 여러 도구의 진입점을 제공합니다. Swttch Desktop은 작업 공간·탭·패널을 소유하므로, 여러 채팅 탭마다 공통 기능을 반복하기보다 데스크탑 셸에서 한 번 제공하는 방향으로 구성합니다.

사용자가 이번 플러그인 배포에 추가한 **상단바 숨기기 옵션**은 이 구상을 위한 준비입니다. 데스크탑이 채팅 주소에 `is_desktop=1`을 붙이면 웹뷰가 상단바를 그리지 않으며(옛 이름은 `top_bar_display`), 제목·favicon·알림·활동 보고 등 채팅 페이지의 동작은 유지합니다. 숨기기만으로 기능 재배치가 완성되는 것은 아니므로, 공통 영역에서 각 기능에 접근하고 조작할 수 있는 연결이 필요합니다.

## 기능의 범위와 배치 방향

| 범위 | 기능 예시 | 배치 방향 |
|------|-----------|-----------|
| 앱·작업 공간 공통 | 프로젝트 탐색, 새 탭, 앱 설정, 공용 자산 라이브러리 | 사이드바·탐색 영역·공통 메뉴 |
| 계정 공통 | 프로바이더 계정, 사용 한도, 초기화 시각, 계정 관리 | 하단바 요약 → 상세 팝오버 |
| 실행 환경 공통 | 백엔드 연결, 실행 작업, 리소스, 포트, 원격 연결 | 하단바 요약 → 상세 관리 |
| 개별 세션 | 대화 내용, 모델, 권한, 컨텍스트, 세션별 작업 상태 | 채팅 내부 또는 활성 작업 뷰와 연결된 도구 영역 |

현재 상단바의 계정·사용량, 예약 메시지, 백그라운드 작업, 터널, 설정, 자산, 새 탭 기능을 이 범위에 따라 분류합니다. 예약 메시지·백그라운드 작업·터널은 실제 데이터와 조작의 범위를 확인한 뒤 위치를 정합니다. 화면에서 공통으로 보인다는 이유만으로 세션별 상태까지 전역 상태로 바꾸지 않습니다.

계정의 사용 한도와 현재 세션의 컨텍스트 사용량은 구분해 표시합니다. 공통 영역에서 계정을 변경하더라도 이미 실행 중인 모든 CLI의 계정을 함께 바꾸는 것으로 간주하지 않습니다. 적용 대상과 시점을 기술 스펙에서 명시해야 합니다.

## Orca 참고

주요 참고 소스로 [공식 홈페이지](https://www.onorca.dev/)와 [공식 저장소](https://github.com/stablyai/orca)를 지속적으로 사용합니다.

제공된 스크린샷과 소스에서 확인한 하단바의 구성은 다음과 같습니다.

| 영역 | 표시 | 상세 기능과 의미 |
|------|------|------------------|
| 왼쪽 | Claude·Codex 아이콘, 사용량 막대, 5시간·주간 비율 | 계정별 사용 한도와 초기화 정보, 계정 선택·관리, 새로고침 |
| 오른쪽 | 메모리 수치, 터미널 수 | 추적 중인 프로세스의 메모리와 터미널 세션 목록·관리 |
| 오른쪽 | 포트 수 | 작업 공간에서 사용하는 포트 조회·열기·관리 |
| 오른쪽 | SSH 연결 상태 | 원격 호스트의 연결 상태와 연결 관리 |

참고할 핵심은 **작은 상시 요약을 클릭하면 상세 정보와 조작으로 이어지는 구조**입니다. 항목별 표시 여부와 좁은 너비에 대응하는 축약 방식도 참고합니다. 모든 기능을 그대로 도입하는 것은 별도 결정 사항입니다.

분석 기준은 Orca 커밋 `6ffbdcd8753b4d028ae36148b50a2c0fb85281b5`이며, [StatusBarSurface](https://github.com/stablyai/orca/blob/6ffbdcd8753b4d028ae36148b50a2c0fb85281b5/src/renderer/src/components/status-bar/StatusBarSurface.tsx)가 소스 진입점입니다. 실제 Orca 앱을 실행한 검증은 하지 않았습니다. 홈페이지의 예시 수치는 실제 사용자 계정 측정값으로 취급하지 않습니다.

비율은 확인한 소스에서 사용량 표시가 기본이고 잔여량 표시도 지원하므로, 스크린샷만으로 잔여량이라고 단정하지 않습니다. 메모리는 PC 전체 메모리가 아닌 추적 대상 프로세스의 합계이며, 터미널 수는 작업 중인 에이전트 수와 동일하지 않습니다. 사용량 수집은 문서의 로컬 전용 설명과 달리 소스에 OAuth HTTP·RPC 경로도 있어 공급자별 구현을 확인해야 합니다.

## 32번 확장킷 SDK 활용과의 연결

확장킷은 확인 당시 `@swttch/extend-kit`의 battery·STT 기능을 제공하며, 전체 채팅 기능을 제공하는 SDK로 간주하지 않습니다. 우선 데스크탑 Node.js 백엔드에서 계정·사용량 기능을 SDK로 사용하고, 공통 React UI가 백엔드 API를 통해 조회·변경하는 구조를 구상합니다.

- SDK는 기능과 데이터를 제공하고, 데스크탑 셸은 표시 위치와 상호작용을 담당합니다.
- CLI·세션 비즈니스 로직은 기존 CCG 백엔드를 재사용합니다.
- 공통 기능은 Electron과 localhost 브라우저에서 같은 React UI와 Node.js 백엔드로 동작해야 합니다.
- 활성 세션에 대한 조작은 대상 세션을 명확히 식별하는 연결 계약이 필요합니다. 숨겨진 상단바의 DOM 조작으로 대신하지 않습니다.

## 구현 전 정할 사항과 수용 기준

1. 기존 상단바 기능별 데이터·조작 범위와 재배치 위치를 확정합니다.
2. 첫 하단바에 넣을 최소 기능을 선정합니다. 계정·사용량과 백엔드 연결 상태를 우선 후보로 둡니다.
3. 확장킷의 계정·사용량 API, 갱신 주기, 인증 보관, 오류 처리를 정합니다.
4. 공통 상태와 활성 세션 상태의 조회·명령 계약, 탭 전환 시 대상 변경을 정의합니다.
5. 기능 진입점을 공통 영역에 마련한 뒤 임베딩 상단바 숨기기를 적용합니다.
6. 브라우저에서 실제 조회·조작, 좁은 너비, 로딩·연결 단절·복구를 검증합니다.

완료 기준은 상단바를 숨겨도 필요한 기능에 접근할 수 있고, 세션별 조작이 올바른 대상에 적용되며, 계정 한도와 세션 컨텍스트가 혼동되지 않는 것입니다. 현재 MVP의 단일 탭·패널 범위는 유지하며 다중 탭 구현은 별도 작업으로 진행합니다.
