# Swttch Desktop MVP 기획과 다음 세션 인계

> 기록일: 2026-10-08, 한국 시간
> 상태: 기획 결정 기록. 구현 착수 전.

## 2026-10-08 MVP 착수 업데이트

- 사용자 추가 확정: 데스크탑 앱이지만 localhost 브라우저에서도 동일하게 사용할 수 있어야 한다. [핵심 원칙](core-principles.md)으로 기록했다.
- 일반적인 웹뷰 구현·구동·확인은 Codex 브라우저에서 충분하다. Electron 전용 호스트 통합만 별도 검증한다.
- 셸의 Electron preload 의존을 공통 로컬 HTTP API 및 호스트 어댑터로 전환했다. Codex 브라우저에서 프로젝트 열기·실제 CLI 응답을 확인했다. 정적 화면만 보이는 상태는 원칙 충족이 아니다.

- 후속 사용자 지시: “일단 한 번 첫 버전을 만들어보고 수정해나가자”에 따라 실행 가능한 개발 프리뷰를 구현했다.
- 첫 구현: Electron 단일 패널·탭, 기존 백엔드 및 채팅 재사용, 네이티브 프로젝트 선택, SQLite 최근 목록, 수동 재시도와 종료 정리.
- macOS에서 실제 CLI 한 턴 완주를 확인했다. 앱 로그인·중앙 API·패키징은 미구현이며 전체 MVP 완료가 아니다.
- 로그인 미연결 상태를 개발 프리뷰 화면에 명시한다. 출시 로그인 요구사항을 철회한 것은 아니다.
- 초안의 종료 정책을 첫 프리뷰에서는 “창 닫기 및 앱 종료 시 확인 후 백엔드 정리”로 구현했다. 자동 재시작·작업 자동 재개는 없다. 사용자 검수 대기.

- [MVP PRD와 수용 기준](mvp-prd.md), [기술스펙 초안](mvp-technical-spec.md)을 작성했다. 전체 요구사항은 사용자 검수 대기이며 구현 상태는 위 업데이트와 README를 따른다.
- 사용자 추가 확정: 앱 로그인에 Google·GitHub·이메일을 모두 지원한다.
- 사용자 추가 확정: 기존 플러그인 사용자는 기존 Swttch 계정을 재사용할 수 있어야 한다.
- 아래 인증 관련 미정 항목 중 로그인 수단은 위 결정으로 구체화됐다. 공급자·이메일 인증 방식·기존 계정 연동 계약은 미정이다.
- 소스 확인상 기존 백엔드의 후원 기능은 키 기반이며 별도 앱 로그인 계약과 구분된다. 기존 계정 원천 확인이 필요하다.

Swttch Desktop은 에이전트를 다루는 개발환경인 ADE다.
장기적으로 여러 독립 애플리케이션을 탭에 담고 패널을 자유롭게 배치한다.
MVP는 **패널 하나에 탭 하나를 두고, 기존 스위치 채팅 웹앱을 안정적으로 실행하는 것**부터 만든다.
이 문서는 2026-09-09의 초기 구상과 2026-10-08 대화에서 확정한 내용을 이어받기 위한 기록이다.

## 확정된 제품 구조

```text
패널 영역
└─ 패널 하나
   └─ 탭 하나
      └─ 기존 플러그인의 채팅 웹앱
```

최종 제품에서 패널 영역은 여러 패널을 담고, 각 패널은 하나 이상의 탭을 담는다.
패널은 위치와 배치를 위한 플레이스홀더다.
각 탭은 스스로 독립된 프론트 애플리케이션이며, 기본 형태는 React 웹앱 또는 터미널 세션이다.
따라서 모든 탭을 채팅 세션과 동일한 개념으로 취급하지 않는다.

앱은 기존 스위치 플러그인을 의존성으로 사용한다.
플러그인은 개별 채팅 세션에 특화되고, 데스크탑 앱은 작업 공간과 애플리케이션을 담는 역할을 맡는다.
채팅 화면은 플러그인의 기존 웹뷰를 재사용한다.

## 확정된 MVP 범위

- Electron 기반 설치형 데스크탑 앱.
- 패널 하나와 탭 하나에서 기존 채팅 웹앱 실행.
- 앱 로그인 필수.
- 로컬 Node.js 백엔드 재사용.
- 앱 홈 디렉토리는 `~/.swttch`.
- 로컬 DB는 SQLite.
- 로컬 서버와 별도의 중앙 API 서버 운영.
- 중앙 서버 DB는 PostgreSQL.
- 중앙 서버의 초기 역할은 계정과 라이선스 관리이며, 추후 점진적으로 확장.
- 설치 프로그램 외에 pnpm과 Homebrew Cask를 통한 설치 경로도 제공.
- 기존 결정상 대상 OS는 macOS, Windows, Linux.

프로젝트와 세션의 중앙 동기화는 현재 중앙 서버의 범위에 포함하지 않는다.
라이선스 정책과 과금 정책은 아직 없다.
필수 앱 로그인을 Agent CLI의 로그인으로 대체하지 않는다.

## 아키텍처 방향

```text
Electron 데스크탑 셸
       │
       ├─ 패널과 탭에 채팅 웹앱 표시
       │               │ WebSocket
       └─ 로컬 Node.js 백엔드 실행 및 관리
                       ├─ Agent CLI
                       ├─ 로컬 파일 및 설정
                       ├─ SQLite
                       └─ 중앙 API 서버
                                  └─ PostgreSQL
```

Electron 셸은 창과 탭, 네이티브 기능 및 앱 생명주기를 담당한다.
로컬 비즈니스 로직은 기존 Node.js 백엔드에 유지한다.
Electron 메인 프로세스에 세션 및 CLI 로직을 중복 구현하지 않는다.
중앙 API 서버의 구현 언어와 프레임워크는 아직 정하지 않았다.

SQLite에 저장할 데이터와 스키마, 중앙 API 호출 주체와 인증 토큰 보관 방식은 기술스펙에서 정한다.
SQLite 채택 자체가 Agent CLI의 원본 JSONL을 DB로 이전하겠다는 결정은 아니다.
기존 원본 데이터 보존 원칙을 유지하고, 전달 과정에서 필드를 리네이밍하거나 누락시키지 않는다.

2026-09-09에는 기존 standalone 배포 산출물 `claude-code-gui-standalone-v<ver>.tgz`를 번들하기로 선택했다.
현재 Electron에서의 실행 방식과 개발 중 로컬 소스 연동은 아직 설계하지 않았다.
기존 사용자용 standalone 산출물 이름을 임의 변경하지 않는다.

## 후속 제품 범위

첫 버전 논의의 중심 사용 장면은 여러 에이전트 세션을 나란히 관리하며 작업하는 것이었다.
이후 사용자가 MVP를 단일 패널과 단일 탭으로 축소했으므로, 아래 항목을 첫 구현에 포함하지 않는다.

- 여러 탭과 여러 패널.
- iTerm2 방식의 `⌘D`와 `⇧⌘D` 종횡 분할.
- VS Code 및 JetBrains 에디터 영역처럼 자유로운 패널 배치.
- 터미널 및 다른 웹앱을 담는 탭.

분할 방향별 단축키 매핑, 분할 직후 표시할 화면, 드래그 이동 규칙과 레이아웃 복원은 아직 상세 확정되지 않았다.
같은 창에 여러 프로젝트를 섞을지, 동일 프로젝트 세션끼리 작업 폴더를 공유하거나 worktree로 분리할지도 미정이다.

## Electron 선택 배경

2026-10-08에 사용자가 Electron으로 진행하기로 확정했다.
기존 Node.js 백엔드와 웹앱을 재사용하고, 향후 여러 독립 웹앱을 담는 구조를 고려한 선택이다.
Tauri가 이 제품을 구현할 수 없다는 판단은 아니다.
실제 설치 크기, 메모리와 성능은 아직 측정하지 않았다.

같은 날 확인한 비교 제품의 데스크탑 셸은 모두 Electron이었다.

| 제품 | 확인 근거 |
|---|---|
| Claude Desktop | 로컬 macOS 앱 v2.26454.2의 `Electron Framework.framework`, `app.asar`, 패키지 `@ant/desktop` |
| OpenAI Codex | 로컬 `ChatGPT.app` v26.928.21956의 패키지 `openai-codex-electron`과 `ElectronAsarIntegrity` |
| 오르카 | [공개 package.json](https://github.com/stablyai/orca/blob/main/package.json)의 Electron 실행 및 빌드 구성 |
| 파세오 | [공식 아키텍처](https://github.com/getpaseo/paseo/blob/main/docs/architecture.md)와 [데스크탑 package.json](https://github.com/getpaseo/paseo/blob/main/packages/desktop/package.json) |

구조 비교의 근거는 [Electron 프로세스 모델](https://www.electronjs.org/docs/latest/tutorial/process-model), [WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view), [Tauri 웹뷰 버전](https://v2.tauri.app/reference/webview-versions/), [Tauri 자식 웹뷰 API](https://v2.tauri.app/reference/javascript/api/namespacewebview/), [Tauri sidecar](https://v2.tauri.app/develop/sidecar/)다.
제품별 내부 선택 이유는 확인하지 않았다.

## 미정 사항

| 항목 | 다음에 구체화할 내용 |
|---|---|
| 첫 실행 | 로그인 방식, 프로젝트 선택, CLI 설치와 인증 확인, 준비 실패 시 안내 |
| 인증 | 계정 공급자, 중앙 API 명세, 로그인 유지와 로그아웃, 오프라인 및 중앙 서버 장애 시 허용 동작 |
| 라이선스 | 권한 범위와 검증 방식. 과금이나 기능 제한을 임의로 만들지 않음 |
| 로컬 데이터 | `~/.swttch` 내부 구성, SQLite 저장 대상과 마이그레이션, 인증 비밀 보관 방식 |
| 종료 | 창 닫기와 앱 종료의 구분, 실행 중 Agent CLI와 백엔드 처리 |
| 복구 | 백엔드 장애 감지와 재연결, 세션 복원과 실행 자동 재개의 구분 |
| 배포 | OS별 설치 산출물, pnpm 설치 동작, Homebrew Cask 배포와 업데이트 방식 |
| 코드 공유 | standalone tgz 번들과 Electron 런타임의 호환, 개발 시 소스 연동 |

초기 대화에서 백엔드 수명은 앱 수명과 같게 하기로 선택했지만, 세부 종료 정책은 확정되지 않았다.
이번 대화에서 제안한 “앱 종료 시 작업 중단, 재실행 시 대화 복원, 자동 작업 재개 없음”과 “백엔드 장애 시 재시작 및 재연결”은 **사용자 확정 전 제안**이다.
이를 승인된 동작으로 구현하지 말고 다음 세션에서 구체화한다.

## 다음 세션의 시작점

1. 이 기록을 읽고 단일 패널과 단일 탭이라는 MVP 범위를 유지한다.
2. **첫 실행 → 앱 로그인 → 프로젝트 선택 → 기존 채팅 웹앱에서 한 턴 완주** 흐름의 PRD와 수용 기준을 정한다.
3. 미정 사항 중 그 흐름에 필요한 결정을 사용자와 구체화한다.
4. PRD와 구분된 기술스펙으로 Electron 셸, 기존 백엔드 실행, 데이터 및 인증 경계를 설계한다.
5. 기존 플러그인 및 standalone 동작을 보존하면서 구현한다.

설치 앱 이름은 **Swttch**, 저장소와 내부 문서의 이름은 **Swttch Desktop**이다.

2026-10-08 기록 시점에는 이 디렉토리에 자체 `.git`이나 구현 소스가 없다.
저장소 생성과 원격 공개는 별도 작업이며 이 기록 저장 과정에서는 수행하지 않았다.
